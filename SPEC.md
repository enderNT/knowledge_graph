# SPEC

§G

Build canonical readable traces for new `IngestionJob` executions, alongside existing operational logs.

§C

C1: scope first = narrow end-to-end trace slice for ingestion.
C2: canonical traces apply only to new executions; no migration, no reconstruction from old logs.
C3: existing `ObservabilityLog` / `LogRun` remain operational, not semantic trace source.
C4: trace writes use buffer-in-memory, persist-on-close.
C5: hard process death before close may lose buffered trace; accepted blind spot.
C6: trace failure must not change ingestion job result.
C7: visible trace copy in Spanish, deterministic, backend-owned, template file dedicated.
C8: LLM boundary payloads store exact request input + exact response output, full, no silent truncation.
C9: embedding boundary detail stores metadata only: provider/model, text length, dimensions, hash; no full vector by default.
C10: DB raw queries excluded from canonical trace; semantic effects only.
C11: first UI = list + detail + text export; no analytics dashboard first.
C12: tests prioritize backend contract before UI/browser checks.

§I

I.api: `GET /v1/traces` → list `TraceSummary`
I.api.detail: `GET /v1/traces/{trace_id}` → header + steps + decisions + details
I.api.export: `GET /v1/traces/{trace_id}/export` → `text/plain`
I.store: ArcadeDB canonical trace storage → trace header + trace events/details
I.obs: `/v1/observability/*` → unchanged operational logs
I.ui: `observability-ui` → trace list/detail/export views
I.copy: dedicated backend trace copy templates → Spanish labels/summaries
I.ingestion: `app/ingestion.py` → first canonical trace producer
I.llm: `app/ai_provider.py` → expose LLM boundary request/response for trace detail
I.embed: embedding providers → expose metadata, not vectors

§V

V1: ∀ canonical trace → recorded by new trace contract; never inferred from `ObservabilityLog`
V2: `trace_id` ≠ `execution_id`; for ingestion `execution_id = job_id`
V3: Trace API reads canonical trace model only; observability API remains operational
V4: ∀ trace event → `type` ∈ closed vocab & `status` ∈ closed vocab
V5: UI visual treatment derives from `type + status`, not payload heuristics
V6: ∀ trace step → one event pairs relevant input + outcome; no start/end split
V7: ∀ trace → sequence monotonic per trace & immutable after persist
V8: Reading order may differ from forensic sequence only in presentation/export
V9: ∀ nested decision → parent linked by explicit parent identity, not by name/proximity
V10: LLM boundary payload persist exact full input/output; silent truncation forbidden
V11: Oversize boundary payload → explicit failure/review marker; never partial-success silently
V12: Embedding trace detail excludes full vector unless later explicitly approved
V13: DB canonical trace captures semantic effects, not raw queries
V14: Trace copy generated by deterministic Spanish templates; LLM never writes titles/summaries
V15: Trace buffer persists on execution close; logical failures still emit `ingestion_failed`
V16: Trace persistence failure logs operational error & does not fail/alter ingestion result
V17: Trace summary computed once at close; list views do not rescan event detail
V18: Trace export mirrors UI reading order, indentation, Spanish copy, and relevant details
V19: First trace slice proves backend + API + UI before full ingestion instrumentation
V20: Contract tests cover sequence, nesting, copy, payload completeness, persist close, failure path
